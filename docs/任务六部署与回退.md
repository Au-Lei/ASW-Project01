# 任务六：阿里云部署与回退

## 当前部署

- 浏览器入口：`https://47.122.105.169/`。业务程序通过 Nginx 的 443 端口访问，仅在服务器本机 `127.0.0.1:8765` 监听。
- 原有静态网站继续使用 80 端口，未替换其配置或文件。
- 发布目录：`/opt/asw/releases/<时间戳>`；当前版本：`/opt/asw/current`；持久数据：`/var/lib/asw`；服务：`asw.service`。
- AI 密钥、账号和审核记忆属于服务器持久数据，不在发布包中。主密钥在 `/etc/asw/asw.env`，仅管理员可读，备份时必须与数据库一起保护。
- `47.122.105.169` 的 Let's Encrypt IP 证书约六天有效，`asw-certbot-renew.timer` 每日两次检查并在续期后重载 Nginx。

## 发布新版本

1. 本机先运行测试，再执行 `python scripts/build_server_release.py .runtime_tmp/asw-release.zip`；发布包白名单不含 `.env`、数据库和客户单据。
2. 把发布包传到服务器 `/tmp/asw-release.zip`，再运行 `sudo bash /tmp/install_server_release.sh`（脚本须与当前代码版本同步）。
3. 在修改前运行 `sudo install -d -m 700 /var/backups/asw` 和 `sudo env ASW_STATE_DIR=/var/lib/asw /opt/asw/current/.venv/bin/python /opt/asw/current/scripts/backup_data.py /var/backups/asw`，并另行妥善保管 `/etc/asw/asw.env`；新版本启动后检查 `systemctl status asw` 和 `/api/session`，再完成一票上传→提取→核对→导出。
4. 发布前后检查 `sudo nginx -t`、`systemctl is-active nginx` 和原 80 端口网站。

## 回退

- **应用版本回退**：若 `/etc/asw/previous-release` 记录了旧版本，先确认路径确属 `/opt/asw/releases/`，再执行 `sudo ln -sfnT "$(cat /etc/asw/previous-release)" /opt/asw/current` 和 `sudo systemctl restart asw`。数据库与密钥不自动回退；如涉及数据结构变化，先恢复对应的受保护备份。
- **首次部署撤回**：执行 `sudo systemctl disable --now asw`，停用 `/etc/nginx/sites-enabled/asw` 后运行 `sudo nginx -t`、`sudo systemctl reload nginx`。原 80 端口站点保持可用。不要删除 `/var/lib/asw` 或 `/etc/asw/asw.env`，以免丢失账号和 AI 配置。
- **证书诊断**：`sudo /opt/asw-certbot/bin/certbot renew --dry-run --cert-name 47.122.105.169 --non-interactive --no-random-sleep-on-renew`；查看 `systemctl status asw-certbot-renew.timer`。

## 安全检查

- 阿里云防火墙只需公网入站 80、443（以及管理用 22）；不要开放 8765。
- 不要把程序登录密码、AI Key、`/etc/asw/asw.env` 或数据库发送到聊天、GitHub 或公开日志。
- 多人使用时由管理员在服务器终端执行 `sudo -u asw env ASW_STATE_DIR=/var/lib/asw /opt/asw/current/.venv/bin/python /opt/asw/current/scripts/manage_users.py add 用户名`，交由本人输入密码。
